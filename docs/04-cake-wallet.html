不安全的那个是默认值

Cake Wallet · 2020–2021

大白话

这一课的 bug 只有一个默认参数那么大。

有人写了一个方便函数，用来生成随机字节。它有一个开关，叫 secure。
开关的默认值是关着的。

然后生成助记词的那行代码忘了把它打开。

修复是十四个字符。代价是八千多个钱包。

这一课要你记住的不是哪个语言、哪个钱包，是那个 API 的形状：
一个安全相关的开关，默认值在不安全的那一侧。任何这样的 API 都迟早会被漏掉。

这一课还有整门课最重要的一条校准，它两头都砍 —— 见下面。

往下一层

披露之后发生了什么

Cake Wallet 是唯一一个有完整「披露之后」纵向记录的案例，所以它特别值钱。

  • 2021-05 厂商自己发现，大张旗鼓披露，发补丁，要求用户紧急转移资金
  • 2021 年中 峰值 88 BTC 以上躺在弱钱包里
  • 2023 年底 研究者在披露 2.5 年后还发现有余额
  • 2024-05-21 大额恶意转出主要从这天才开始 —— 距公开披露三年

往乐观的方向：弱钥匙不会被瞬间扫光。存在一个真实的、以年计的反应窗口。

往悲观的方向：清扫最终一定会来，而且来的时候是完整且同时的。 三年没动的人，在某一天一次性全部失去。

为什么会有这个窗口？不是运气。机理在第 11 课。

为什么这一课能整个跑完
