一个坏掉的随机数，活了十二年

CryptoJS / Ill Bloom · CVE-2026-71851

大白话

上一课那个「第一个钱包」不是孤例。

一个被几乎所有 JavaScript 项目依赖过的加密库，从 2014 年起自己写了一个随机数生成器。
它吐出来的第一个助记词以 illness blossom 开头。Ill Bloom 这个漏洞名字就是这么来的。

这一课要讲的不只是代码怎么坏的，还有一件更难受的事：
这个 bug 曾经被修好过，然后又被改回去了。

理由是「那个改动破坏了向后兼容」。

所以它不是一次编码失误，是一次组织决策。
而这类失效模式，换成 AI 写代码一点都不会改善 —— AI 甚至会更乐意保持向后兼容。

往下一层

熵在哪里漏掉的

那个生成器有两个状态字。一个是硬编码的常量（零熵）。 另一个是唯一的熵入口，来自 Math.random()。

但它进来之后立刻被切成两半用 —— 只有整数部分的低 32 位有效。 Math.random() 本来有 52 位尾数，剩下的直接扔了。

之后每生成一个 32 位字，只多出两个「符号位」。数一下：

128 位请求（4 个字）：32 位 + 4×2 位 = 40 位
256 位请求（8 个字）：32 位 + 8×2 位 = 48 位

Coinspect 公布的实测口径是 2³⁹ 和 2⁴⁷ —— 和上面这个纸上推演各差约 1 位。量级对得上。

为什么这一课的代码值得跑

课程里带了原版的那段 JavaScript（用 node 跑）和一份 Python 移植， 两边输出逐字节一致。你不用相信任何人的转述， 可以自己看到 Math.random() 返回 0 的时候出来的就是 illness blossom。

自己跑一下

python3 lessons/02_ill_bloom/ill_bloom.py

复现第一个助记词，并和原版 JS 交叉验证。

node lessons/02_ill_bloom/cryptojs_random.js zero 16

直接跑那段原封不动抄下来的 crypto-js 代码。
